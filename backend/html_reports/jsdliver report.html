Cross-Domain Misconfiguration

Count: 2

Count %: (22.2%)

CWE ID: 264

Summary Web browser data loading may be possible, due to a Cross Origin Resource Sharing (CORS) misconfiguration on the web server. Solution Ensure that sensitive data is not available in an unauthenticated manner (using IP address white-listing, for instance). Configure the "Access-Control-Allow-Origin" HTTP header to a more restrictive set of domains, or remove all CORS headers entirely, to allow the web browser to enforce the Same Origin Policy (SOP) in a more restrictive manner. Other Info The CORS misconfiguration on the web server permits cross-domain read requests from arbitrary third party domains, using unauthenticated APIs on this domain. Web browser implementations do not permit arbitrary third parties to read the response from authenticated APIs, however. This reduces the risk somewhat. This misconfiguration could be used by an attacker to access data that is available in an unauthenticated manner, but which uses some other form of security, such as IP address white-listing. Description A Cross Origin Resource Sharing (CORS) misconfiguration on the web server may allow an attacker to access data that is normally only available to authenticated users. This can occur when an unauthenticated user makes a cross-domain read request to an API on the affected domain, and the web browser enforces the Same Origin Policy (SOP) more restrictively due to the CORS misconfiguration. The vulnerability can be exploited by an attacker who is aware of the CORS misconfiguration and can make cross-domain read requests to the API, potentially accessing data that would normally only be available to authenticated users. The solution to this vulnerability is to ensure that sensitive data is not available in an unauthenticated manner (using IP address white-listing, for instance) and to configure the "Access-Control-Allow-Origin" HTTP header to a more restrictive set of domains, or remove all CORS headers entirely, to allow the web browser to enforce the Same Origin Policy (SOP) in a more restrictive manner..

This rule identifies situations where weak authentication methods are used, which can potentially expose sensitive information to unauthorized access. The rule checks for the following conditions:

- Basic authentication with a weak password, such as "password" or "qwerty". - Basic authentication without a password set. - Kerberos authentication with a weak password, such as "password" or "qwerty". - LDAP authentication with a weak password, such as "password" or "qwerty". If any of these conditions are met, the rule will trigger an alert, informing the user that weak authentication is being used and suggesting alternative methods to improve security..
