Description of Vulnerabilities:

1. Missing Anti-clickjacking Header:

The absence of an anti-clickjacking header in the HTML document can lead to clickjacking attacks.

2. Multiple X-Frame-Options Header Entries:

The presence of multiple X-Frame-Options header entries can make it difficult for web browsers to determine which frames are allowed to be displayed, potentially leading to clickjacking attacks.

3. X-Frame-Options Defined via META:

In some cases, the X-Frame-Options header is defined via the META tag, which may not be compliant with the specification.

4. X-Frame-Options Setting Malformed Code:

The X-Frame-Options header may be set with malformed code, which can also lead to clickjacking attacks.

Description of Mitigation:

- Implement an anti-clickjacking header in the HTML document.

- Limit the number of X-Frame-Options header entries to one.

- Ensure that the X-Frame-Options header is defined only in the HEAD section of the HTML document.

- Set the X-Frame-Options header with valid and compliant code..

X-Content-Type-Options Header Missing

Count: 3

Count %: (25.0%)

CWE ID: 693

Summary The Anti-MIME-Sniffing header X-Content-Type-Options was not set to nosniff. This allows older versions of Internet Explorer and Chrome to perform MIME-sniffing on the response body, potentially causing the response body to be interpreted and displayed as a content type other than the declared content type. Current (early 2014) and legacy versions of Firefox will use the declared content type (if one is set), rather than performing MIME-sniffing. Solution Ensure that the application/web server sets the Content-Type header appropriately, and that it sets the X-Content-Type-Options header to 'nosniff' for all web pages. If possible, ensure that the end user uses a standards-compliant and modern web browser that does not perform MIME-sniffing at all, or that can be directed by the web application/web server to not perform MIME-sniffing. Other Info This issue still applies to error type pages (401, 403, 500, etc.) as those pages are often still affected by injection issues, in which case there is still concern for browsers sniffing pages away from their actual content type.
